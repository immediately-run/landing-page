### Fork the app.

Open the app in the editor to fork it. A fork is yours to change, but it starts with no access to your data — capabilities are granted, never assumed.

<DeepLink label="Fork this app in the editor →" href="/edit/github/immediately-run/file-selector/main/files/src/App.tsx" />

### Request a folder.

The app asks for access through the SDK. It does not reach for a path, and it does not ask for a mode — it calls the request method and the host hands control to you. The call REJECTS when you decline, so handle it as an error, not as a falsy result.

<CodeBlock route="src/lib/grant.ts">

```tsx
import { requestMount } from '@immediately-run/sdk';

try {
  const mount = await requestMount();
  // The USER chose ro or rw — read it back, never assume it.
  const writable = mount.mode === 'rw';
} catch (e) {
  // 'cancelled' | 'forbidden' | 'auth-required' — degrade, do not crash.
}
```

</CodeBlock>

### Grant access in the host prompt.

The platform draws the consent prompt — the app never imitates it. You pick one project folder inside a space, and you choose read-only or read-write explicitly; there is no default, and the app cannot ask for one. Access is asked for, not taken.

<Checkpoint alt="host consent prompt for a folder grant">

</Checkpoint>

### Read and write through the mount.

The granted folder is now a mount in the app’s world. It reads and writes within that one mount and nowhere else — a read-only grant fails writes with EROFS, which the app degrades around.
